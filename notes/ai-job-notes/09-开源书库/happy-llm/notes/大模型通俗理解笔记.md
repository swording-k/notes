# 大模型通俗理解笔记

> 读《Happy-LLM》时的通俗版理解，用来在卡壳处快速恢复直觉。覆盖第 1~7 章：发展脉络、Transformer、预训练、LLM、RAG。

---

## 0. 术语与发展脉络（缩写的全称都在这）

一句话主线：**统计机器学习 → 深度学习 → NLP 的序列模型 → 预训练语言模型（PLM）→ 大语言模型（LLM）→ 训练对齐 → 应用（RAG / Agent）。**

### 0.1 逐层往上

1. **AI（Artificial Intelligence，人工智能）**：让机器表现出智能的大目标。1956 年达特茅斯会议提出这个词。
2. **ML（Machine Learning，机器学习）**：不写死规则，让程序从数据里自己找规律。代表：线性回归、**SVM（Support Vector Machine，支持向量机）**、决策树、随机森林。这一阶段靠人手工设计特征。
3. **DL（Deep Learning，深度学习）**：机器学习的子集，用多层 **NN（Neural Network，神经网络）** 自动学特征，不再靠人挑特征。2012 年 AlexNet 在 ImageNet 上打爆对手，靠的是 **CNN（Convolutional Neural Network，卷积神经网络）** + GPU。
4. **NLP（Natural Language Processing，自然语言处理）**：让机器处理人类语言。往下分 **NLU（Natural Language Understanding，自然语言理解）** 和 **NLG（Natural Language Generation，自然语言生成）**。
   - 早期用 **RNN（Recurrent Neural Network，循环神经网络）** 逐词读，句子一长就忘前面；**LSTM（Long Short-Term Memory，长短期记忆网络）** 加门控缓解遗忘。
   - 翻译用 **Seq2Seq（Sequence to Sequence，序列到序列）**：一个 RNN 读（encoder），一个 RNN 写（decoder）。
   - Seq2Seq 读完只给一个定长向量，信息挤不下，于是加 **Attention（注意力机制）**：写每个词时回头再看源句的相关部分。
5. **Transformer（2017，论文《Attention Is All You Need》）**：把 attention 做成唯一主力，扔掉 RNN，可以并行训练。就是第 2 章那张图纸。
6. **PLM（Pre-trained Language Model，预训练语言模型）**：先在大量无标注文本上预训练，再小改一下适配具体任务（**fine-tuning，微调**）。代表：
   - **BERT（Bidirectional Encoder Representations from Transformers）**：encoder-only，任务是 **MLM（Masked Language Modeling，掩码语言建模）**，也就是完形填空。
   - **GPT（Generative Pre-trained Transformer）**：decoder-only，任务是预测下一个词。
   - **T5（Text-to-Text Transfer Transformer）**、**BART（Bidirectional and Auto-Regressive Transformers）**：encoder-decoder，一切任务都写成「文本进、文本出」。
7. **LLM（Large Language Model，大语言模型）**：PLM 把参数和数据推到百亿以上量级，出现 **emergent abilities（涌现能力）**。参数规模与效果之间的经验规律叫 **Scaling Law（缩放定律）**。
8. **训练三步曲**：**Pre-training（预训练）** → **SFT（Supervised Fine-Tuning，有监督微调）** → **RLHF（Reinforcement Learning from Human Feedback，基于人类反馈的强化学习）**。
   - RLHF 里常用 **PPO（Proximal Policy Optimization，近端策略优化）**；不用奖励模型的替代路线是 **DPO（Direct Preference Optimization，直接偏好优化）**；DeepSeek-R1 用的是 **GRPO（Group Relative Policy Optimization，组相对策略优化）**。
   - 省显存微调用 **LoRA（Low-Rank Adaptation，低秩适配）**、**QLoRA（Quantized LoRA，量化版 LoRA）**。
9. **应用层**：**RAG（Retrieval-Augmented Generation，检索增强生成）**、**Agent（智能体）**、**Function Calling（函数调用）**、**MCP（Model Context Protocol，模型上下文协议）**。
10. **随时会撞见的其他缩写**：
    - **Token**：模型眼里最小的文本单位；切词工具叫 **Tokenizer**，常见算法 **BPE（Byte Pair Encoding，字节对编码）**。
    - **Embedding（嵌入）**：把文本映射成一串数字（向量）。
    - **MoE（Mixture of Experts，混合专家）**：每次只激活一部分参数，省算力。
    - **ICL（In-Context Learning，上下文学习）**：不训练，只在提示词里给几个例子。
    - **CoT（Chain of Thought，思维链）**：让模型把推理步骤写出来再回答。
    - **SOTA（State of the Art）**：当前最好水平。
    - **GPU（Graphics Processing Unit，图形处理器）**：训练用的显卡。

### 0.2 一句话串起来

统计机器学习靠人手设计特征 → 深度学习让网络自己学特征 → NLP 用 RNN/Seq2Seq 处理序列，但慢且健忘 → Transformer 用注意力一次性解决并行和长依赖 → 先用海量文本预训练出 PLM（BERT 偏「懂」，GPT 偏「写」）→ 把模型和数据推到极大规模得到 LLM → 再用 SFT 和强化学习让它听话、会推理 → 最后用 RAG 补知识、用 Agent 补行动。

## 1. Transformer 是一张图纸，不是一种模型

Transformer 不是一类模型，而是一张「文字加工流水线」的图纸。

你给它一句话，它做两件事：

1. 把句子切成词，每个词变成一串数字（向量）。
2. 核心动作叫「注意力」：让每个词去和句子里其他所有词对视一遍，判断谁跟自己关系大，把有用的信息吸收过来。

这样同一个「苹果」，在「我吃苹果」和「苹果开发布会」里，得到的两串数字就不一样。这步是 Transformer 真正的创新，也是它名字的由来。

---

## 2. 原始 Transformer 为什么有两个部件

因为它最初是为**翻译**设计的。翻译天然是两步：

- 源语言（如中文）先被读懂、理解整句话；
- 再把它写成一个新句子（英文），一个词一个词往外蹦。

于是图纸被分成两块：

- **Encoder = 阅读理解。** 把整句话一次性全读进去，每个词都能看到它前面和后面的所有词（双向）。它输出的不是翻译，而是对这句话的一份「理解」。
- **Decoder = 写作文。** 一个字一个字往外写。写每个字时只能看前面已经写出来的内容，不能偷看后面。因为训练时若它能看答案，就学不到真本事。

所以原始 Transformer 就是 encoder 读中文、decoder 写英文，两边配合。

---

## 3. BERT 和 GPT 各自裁掉了什么

**BERT 只留 encoder。**

- 预训练任务：完形填空。把句子里一些词盖住，让模型根据上下文猜出来。
- 要猜被遮住的词，必须能同时看前后文，所以 encoder 的双向特性正合适。
- 结果：擅长「理解」类活儿，如文本分类、情感分析、判断两句话是否一个意思。
- 但它没有往外写的能力，让它接着写一段话，它做不了。

**GPT 只留 decoder。**

- 预训练任务：续写。给一段文字，预测下一个词是什么，把预测的词接上去，再预测下一个，一直滚下去。
- 单向是必须的，因为预测下一个词这件事本来就不允许看未来。
- 结果：擅长「生成」类活儿，对话、写作、翻译、写代码，全都算续写。

---

## 4. 关键澄清：decoder 不是「预训练」，任务决定模块

不是「decoder 对应预训练」。**BERT 和 GPT 都是预训练的。**

区别是预训练任务不一样，而任务反过来决定了该用哪个模块：

- BERT 选的任务是完形填空，需要双向看全文 → 用 encoder。
- GPT 选的任务是续写，只能单向看前文 → 用 decoder。

顺序是：**先有任务，再选模块**，不是先选模块再套任务。

---

## 5. GPT 没有 encoder，那它怎么「读懂」你的话

**decoder 不是只会写，它同时也在读。读和写用的是同一套零件。**

原始 encoder-decoder 是两个人配合：encoder 把中文读懂变成一叠「理解笔记」，decoder 拿着这叠笔记去写英文，是两套分开的零件。

GPT 把它们合并了。处理提示词时：

- 你的话被切成词，一个词一个词进模型；
- 每进去一个词，模型就用注意力让它和前面所有词对视，把关系算进来；
- 这个算出来的中间状态，**就是「理解」本身**。

也就是说，GPT 理解你的话，不是先翻译成一叠笔记再开口，而是**理解这个动作和它脑子里正在生成的状态是同一个东西**。它边读边想，读完那一刻，脑子里已经装满了对整段话的把握，然后顺着这个状态往下写。

打个比方：一个人听你说话，他脑子里形成的理解不是一个先存进盒子再拿出来用的东西。理解就长在他的意识里，他开口回应是从同一个意识里流出来的。GPT 也是这样。

> encoder 的双向能力确实更强一点，但 GPT 用单向也够用。因为提示词里**最后一个词在计算时，已经通过前面所有词间接「见过」整段话了**。信息一层层往上传，越靠后的词携带的上下文越完整。

一句话：**GPT 的「理解」不是一个独立模块，而是「预测下一个词」练出来的副产品。**

---

## 6. LLM 理解提示词为什么不用 encoder（不是为了省性能）

这点容易误解。如果只算「读懂提示词」这一步，encoder-decoder 反而可能更省：encoder 把提示词一次性编码完，生成时只用 cross-attention 回看，编码成本被摊薄。

主流 LLM 砍掉 encoder，真正原因是：

1. **一套零件干所有活。** 把「理解」任务也改写成「续写」：「判断这句话的情感：___」「翻译这段话：___」「根据上文回答：___」。这样预训练、微调、对齐全都是同一个 next-token prediction，不用维护两套模块、两套训练目标。
2. **架构简单，容易做大。** decoder-only 就是一堆相同的 block 叠起来，训练并行度高，scaling law 研究得最透。encoder-decoder 多一组 cross-attention，结构更复杂，大规模训练和对齐更难调。
3. **提示词和输出在同一条流里。** 你的话和模型的回答，对 decoder 是一串连续 token，顺着往下写即可。in-context learning、few-shot、思维链，本质都是「往前缀里塞东西然后续写」，decoder-only 天然适配。
4. **经验上更划算。** 大规模 decoder-only + next-token prediction 涌现出指令遵循、in-context learning 等能力；BERT 那种 encoder-only 根本不会生成，干不了通用助手。

> encoder-decoder 并没有消失（T5、BART 这类翻译/摘要模型还在用），只是在通用大模型这条路上 decoder-only 赢了。

## 7. 预训练怎么把互联网信息「压进参数」

先纠正直觉：**参数里存的不是信息，而是规律。**

模型不是把几万亿个词背下来塞进硬盘，而是练出「手感」——语言里各种东西之间的关联和规律。

训练过程一句话：**不断玩「完形填空」，猜错了就微调几百亿个数字。**

1. 拿一段真实文本，如「法国的首都是巴黎」。
2. 把最后一个词「巴黎」挡住，让模型猜下一个词。
3. 模型在词表里给每个词一个概率，如「巴黎 0.7、伦敦 0.2、柏林 0.05……」。
4. 和标准答案对比，算出「猜错程度」（损失）。
5. **反向传播**：算出几百亿个数字里每一个该往哪个方向调一点点，能让下次猜得更准。
6. 调完换下一段文字，重复。

这个「调数字」的动作重复几万亿次，就是训练。

**为什么「猜下一个词」这么简单的目标能练出知识？**

因为要猜准，模型被迫学背后所有的东西：

- 要猜准「法国的首都是___」，它必须知道「法国」和「巴黎」的关系；
- 要猜准「他推开___，走进房间」，它得知道「门」常和「推开、走进」搭配；
- 要猜准「Python 里用来循环的关键字是___」，它得知道 Python、循环、for 这些概念的关系。

目标简单，但要做好它，模型就必须把语法、常识、事实、逻辑、语气和风格，全都压进那几百亿个数字里。这就是「压缩」的真相——不是有损压缩文本，而是**把人类文本里的规律提炼出来，存进参数**。

**规模感：**

- GPT-3：1750 亿参数，训练数据几万亿词，几千张 GPU 跑几周甚至几个月。
- GPT-4 更大，具体数字未公开。
- 「训练要很久」本质就是「猜词—调数字」循环重复了天文数字次。

**知识存在哪？** 不是某一个参数。你找不到哪一个数字存着「巴黎」。知识**分散**在几百亿个参数的组合关系里，就像找不到大脑里哪一个细胞存着「自行车平衡感」——它是整个网络的状态。

## 8. 词向量坐标的正确图景（修正一个常见直觉）

大方向对：训练完后有一个超级庞大的多维空间，每个词有坐标，预测下一个词就是根据前文在坐标系里定位、找最匹配的词。

但有两处要修正：

**修正一：词不是「一个固定坐标」，而是「每个位置一个动态坐标」。**

刚进模型时，同一个词确实共用同一个初始向量（embedding）。但每经过一层 attention，这个词的向量都会和上下文里的其他词混合一次。所以「苹果」在「我吃苹果」和「苹果开发布会」里，越往后的层坐标差得越远。不存在一张全局固定的「词坐标表」。

**修正二：预测不是「找最近的词」，而是「打分」。**

最后一层输出一个向量，模型拿它和词表里每个词的向量做点积得到分数，再 softmax 成概率。分数最高的词概率最大，但不是绝对选它——实际会按概率采样（温度、top-p 控制随机性），所以同一个问题可能得到不同回答。说「越对齐分越高」比「距离最近」更准确。

**「理解也是这样」——完全正确。**

理解没有独立步骤。就是这些向量在一层层 attention 里被反复更新，越靠后的位置吸收的上下文越全。读完提示词那一刻，最后一个位置的向量已经装满对整段话的把握，模型顺着它继续写。**理解 = 生成前的那个状态**，不是另找一个「理解坐标」。

一个更准的图景：

- 词向量 = 坐标，但会随上下文漂移；
- 预测 = 输出一个向量，和词表所有向量比对齐程度，转成概率分布再采样；
- 理解 = 同一套向量在 attention 中不断更新，与生成共用同一套零件。

## 9. 一句话记忆

- Encoder 像阅读理解，双向通读全文。
- Decoder 像写作文，只看前文往下写。
- BERT 只做阅读理解，所以会分析不会写。
- GPT 只做写作文，所以会写；而「会写」做强了，对话、答题、翻译就都包含进去。
- 后来的大模型几乎全是 decoder-only，因为生成比理解更通用，连「理解」都能改写成「根据这段文字回答我」这种续写形式。
- 预训练不是背文本，是练手感：猜词、改数字，重复几万亿次，把语言的规律压进参数。

## 10. RAG：把「查资料」接在大模型前面

RAG 一句话：**先从你的文档里检索出最相关的几段，塞进提示词，让模型看着资料回答。**

它解决三个问题：模型不知道你的私有文档；模型的知识有截止日期；模型会一本正经胡说（幻觉）。因为答案有出处，所以可追溯。

代码在 `docs/chapter7/RAG/`，5 个文件对应 5 步。先记住一个大前提：**RAG 全程不训练，不改模型一个参数。** 换数据只换文档，不动权重。

### 10.1 Step 1 导入文件（utils.py 的 ReadFiles）

`ReadFiles('./data')` 递归遍历目录，只收三类文件：`.md`、`.txt`、`.pdf`。

- pdf：用 PyPDF2 一页页抽文字。
- md：先转成 HTML，再用 BeautifulSoup 取纯文本，顺手用正则删掉 http 链接。
- txt：直接读。

关键点是**把各种格式统一成纯文本**。后面的步骤只认文本，不认格式。

### 10.2 Step 2 切分（get_chunk，max_token_len=600，cover_content=150）

为什么必须切：一篇文档几万字，全塞进提示词又贵又超长，而且检索粒度太粗——你要的是「相关的那一段」，不是整本书。

做法：用 tiktoken 的 `cl100k_base` 数 token。真正的块上限 = 600 − 150 = **450 token**，然后按行往块里累加，超了就开新块。

**重叠是重点**：新块开头会粘上上一块的最后 150 个字符（代码里 `cover_part` 那段）。因为切分点经常正好切在一句话中间，两边各留一半，谁都不完整。重叠让边界内容在两块里都出现一次，检索命中率就上去了。

另外，遇到单行超过 600 token 的极端情况（比如一大段没有换行的代码），会按 token 硬切。

### 10.3 Step 3 向量化（Embeddings.py）

`OpenAIEmbedding` 走的是 OpenAI 兼容接口（示例里配的是硅基流动），模型默认 `BAAI/bge-m3`。它把一段文本压成一个固定长度的高维向量——**意思相近的文本，向量方向也相近**。

注意：这是**另一个模型**，跟聊天模型不是一个东西。检索用 embedding 模型，回答用 chat 模型，两个模型分工。

同一文件里还有 `cosine_similarity`：两个向量点积除以两个长度之积。只看方向、不看长短。因为文本长短会直接影响向量长度，方向才代表「意思像不像」。

### 10.4 Step 4 向量数据库（VectorBase.py 的 VectorStore）

这个「数据库」极其朴素，就是两个列表：一个存所有文本块，一个存对应的向量。

- `get_vector`：逐条调 embedding 接口算向量。
- `persist`：存成两个 json（`vectors.json`、`doecment.json`）。**`doecment` 是原始代码里的笔误**，读和写用的是同一个错名字，所以能跑。
- `load_vector`：下次启动直接读本地文件，不用重算。
- `query`：把用户问题也向量化，和库里每一条算余弦相似度，`argsort()[-k:][::-1]` 取分数最高的 k 条返回。

真实项目不会这么干。几千条还能暴力全算，几百万条必须换成 FAISS、Milvus、Qdrant、pgvector 这类，用 **ANN（Approximate Nearest Neighbor，近似最近邻）** 索引来做近似查找。Tiny-RAG 用 numpy 全量算，目的是让你一眼看懂「向量检索」到底在算什么。

### 10.5 Step 5 大模型模块（LLM.py）

核心是这个提示词模板，它干三件事：

1. **给资料**：把检索到的 `context` 填进去。
2. **给问题**：填 `question`。
3. **给退路**：「如果给定的上下文无法让你做出回答，请回答数据库中没有这个内容」——这句话很重要，它把「瞎编」变成「承认不知道」的合法选项。

参数上 `temperature=0.1`，压低随机性，让回答贴着资料走，别自由发挥。`history` 传空列表，说明这里是无多轮的单次问答。

### 10.6 demo.py：五步串起来（一共 12 行）

```python
docs = ReadFiles('./data').get_content(max_token_len=600, cover_content=150)
vector = VectorStore(docs)
embedding = OpenAIEmbedding()
vector.get_vector(EmbeddingModel=embedding)
vector.persist(path='storage')

question = 'RAG的原理是什么？'
content = vector.query(question, EmbeddingModel=embedding, k=1)[0]
chat = OpenAIChat(model='Qwen/Qwen2.5-32B-Instruct')
print(chat.chat(question, [], content))
```

读文件 → 切块 → 向量化 → 落盘 → 用问题时向量化查 top-k → 拼提示词 → 调 Qwen2.5-32B 生成。**检索和生成是两段独立的代码，靠一个字符串 `content` 连起来。**

### 10.7 几个容易卡住的点

- **k 取多少**：太小漏信息，太大噪音多还烧 token。demo 里 k=1 是为了跑通，实用一般 3~5。
- **命中的上限由检索决定**：模型只负责把资料讲顺。资料没查到，再强的模型也答不对。所以工程上先调检索，再调生成。
- **切分策略是最被低估的一环**：按固定 token 切只是及格线。真实项目会按标题层级切、按语义切、给每块打 metadata（来源、章节、时间）以便过滤。
- **进阶三件套**：rerank（先召回 20 条再精排取 5 条）、query 改写（用户问题先改写成更好检索的说法）、hybrid search（关键词检索 + 向量检索混着用）。

## 附录：第八章要不要读

先给结论：**要读，而且这可能是全书最值钱的一章。**

判断依据是第八章的目录，四个代码子项目：`grpo`、`opd`、`retool`、`search-r1`。

- **GRPO** 是 DeepSeek-R1 用的强化学习算法，2025 年 1 月随 R1 公开，不是 GPT-4o 时代的老东西。
- **ReTool**、**Search-R1** 是 2025 年的工作，主题是「让模型在强化学习里学会调用工具、自己决定什么时候搜」——这正是当下 Agent 训练的主线。

所以第八章讲的不是过时的 PPO 式 RLHF 综述，而是 **RLVR（Reinforcement Learning with Verifiable Rewards，可验证奖励的强化学习）** 这条线：用「答案对不对」这种能自动判分的奖励，让模型自己练出长推理。o1、R1 之后的推理模型全靠这条路。

顺带一个判断方法：**看一个教程新不新，别看它提到哪个模型，看它有没有 GRPO、RLVR、agentic RL。** 有，就还在前沿。
