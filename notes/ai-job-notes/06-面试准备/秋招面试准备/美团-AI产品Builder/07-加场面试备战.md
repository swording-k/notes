# 07-加场面试（技术交叉面）备战

> 触发：HR 面后，一面面试官（一辉哥，业务团队、握 HC）主动发起，落为正式"加场面试"。
> 真实性质（已向一辉哥确认）：**技术交叉面**——由前端或后端同事来面，考察 **AI 相关、稍微偏技术点**的问题（因岗位是 AI Builder）。
> 核心结论：**这是好信号（你已在 offer 讨论区），且正好是你的强项——你有 Agent 原理储备 + 真实搭建经验，今晚按技术面加固即可，别慌。**

---

## 一、这是什么面（定性）

- 你已走完 一面（业务）+ 二面（深度）+ HR 面，现加一场**技术交叉面**，说明团队想从技术维度再确认你能不能扛 AI Builder 这个"自己写 Demo 的产品经理"岗。
- 交叉面 = 不是你原面试官，是**另一个技术同事**（前端或后端）来面，所以问题会比二面更偏"技术理解 + 你做过的东西"，但不会像纯研发面那样深挖到源码级。
- 一辉哥原话："稍微偏技术点" → **概念性 + 结合你做过的 Agent 经验**，不是考你手写算法/背八股。

---

## 二、技术考点清单（重点，今晚过一遍）

按"概念 → 你的真实抓手 → 怎么答"三栏准备。面试官大概率从你简历/项目里挑点问，所以**每个点都要能接住 + 举自己的例子**。

| 考点 | 你的真实抓手（已有素材） | 怎么答（要点） |
|------|------------------------|----------------|
| **1. 什么是 Agent / AI Agent 原理** | 飞书 PM Agent（Loop：think→act→observe）、FitGenius | Agent = 大模型 + 工具调用（Function Calling）+ 记忆 + 规划/反思的闭环；不是单纯调 API，是"能自主决策下一步"的系统 |
| **2. Loop vs Harness** | 你真实代码：agent.py（Loop 控制流）、harness_bridge.py（Harness 运行底座/白名单沙箱） | Loop=控制流（思考-行动-观察循环）；Harness=运行底座（隔离环境、ALLOWED_TOOLS 白名单限定能调什么）；Agent = Model + Harness |
| **3. MCP 是什么** | 此前文档已厘清：MCP=协议层（类比 USB-C），CLI=文本入口 | MCP 是 Agent 连接外部工具/数据的标准协议，让模型能统一调用不同服务；不是某个软件的 CLI，CLI 只是执行入口之一 |
| **4. 结构化输出 / 防崩容错** | FitGenius：prompt 强制 JSON → extractJSONObject 抠合法 JSON → 本地安全兜底 → 留旧计划 | 大模型输出不稳定，靠"强约束 prompt + 解析兜底 + 失败降级"三件套保证不崩；这是 AI 应用落地的关键工程经验 |
| **5. RAG（检索增强生成）** | 可结合知识库类场景讲 | 把外部知识检索后塞进上下文再生成，解决模型"不知道最新/私有知识"的问题；适合 FAQ、文档问答 |
| **6. 模型选择 / 微调 vs 提示词 vs RAG** | FitGenius 用现有大模型 API + 提示词工程 | 优先提示词+工具调用解决；知识私有/更新频繁用 RAG；只有任务高度专用且数据充足才考虑微调（成本高） |
| **7. 多轮对话 / 状态管理** | FitGenius 的 ChatMessage 结构、AIActionCommand（update_plan/add_exercise/remove_exercise） | 用结构化消息体维护上下文；AI 改计划只走 3 个固定指令，锁定"爆炸半径"避免失控 |
| **8. AI 产品落地的技术权衡** | 你做过的 AI 产品经验 | 成本（每次调用钱）、延迟（响应速度）、准确率（结构化输出+兜底）三者权衡；产品岗要懂这些才能和工程师对齐 |

⚠️ **别死背定义**：面试官更想听"你做的时候怎么想的、踩过什么坑"。上面每栏的"你的真实抓手"才是拉开差距的点。

## 三、被追问时的答题策略（产品+技术复合怎么讲）

你是"产品+技术"背景，技术面里**这是你的差异化优势**，讲法要：

1. **先给概念（一句话）**，证明你懂原理；
2. **立刻接"我做过"**，用 FitGenius / 飞书 PM Agent 举例（真实项目，信手拈来）；
3. **补一句产品视角**——"这个技术点对应的用户价值/产品决策是什么"，显你不是纯写代码的。

> 示范（被问"你怎么保证 AI 不崩"）：
> "我做过一个 AI 健身产品，大模型输出不稳定，我的做法是三层——prompt 强制结构化、解析时抠合法 JSON、失败落本地兜底不静默。这背后是产品思维：用户计划不能因为一次模型抽风就乱掉，所以我把 AI 能改的范围锁死在 3 个固定指令里。技术是为体验服务的。"

这种答法 = 技术硬 + 产品脑，正好是 AI Builder 要的人。

- **FitGenius（AI 健身计划产品）**：iOS 端 AI 产品，核心是用大模型生成/修改健身计划；技术抓手=结构化输出 + 防崩三件套 + 3 指令锁爆炸半径。

## 六、红线

- **别编技术细节**：没做过的别说做过；Swift/Python 等具体技术栈只在你确定时提（FitGenius 是你真实 iOS 项目，可讲；不确定的别说"我用 X 框架"）。
- **别只讲技术不讲产品**：技术面里也要偶尔回扣"这解决了什么用户问题"，否则显得不像 PM。
- **别和前几轮矛盾**：你说过"做过 Agent 搭建""产品+技术复合"，今晚讲的技术点要和这口径一致。
- **别慌也别飘**：交叉面同事可能问得细，答不上来就坦诚"这块我实践少，但理解是…"，比硬编强。
