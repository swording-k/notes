# 项目双视角面试问答 · 使用说明

> 用途：把你的 7 个项目，分别按「AI 应用开发岗」和「AI 产品岗」两个视角，列出面试官**可能问的问题 + 回答要点**。
> 配套文件：`01-AI应用开发岗-项目问答.md`、`02-AI产品岗-项目问答.md`

---

## 一、两个岗的问法本质区别

| 维度 | AI 应用开发岗（技术面） | AI 产品岗（产品面） |
|---|---|---|
| 面试官想确认 | 你能不能把这个东西**做出来、做稳** | 你能不能**想清楚为谁做、为什么做、做对没有** |
| 问题形态 | "怎么实现的？""为什么选 A 不选 B？""难点怎么解的？" | "用户痛点是什么？""你做了什么取舍？""怎么验证有效？" |
| 主线索 | 架构 / 选型 / 实现 / 量化指标 | 痛点 / 需求 / 决策权衡 / 用户反馈 |
| 致命雷区 | 技术细节编不下去、说不清 trade-off | 沉到实现层变成"讲代码"（你已被多位面试官点过"偏技术"） |
| 你的回答姿态 | "我设计了 X 架构，因为…" | "用户遇到 Y，我决定…，放弃了…" |

**一句话**：开发岗考"会不会做"，产品岗考"值不值得做、做没做对"。同一段经历，两个岗讲的重点完全不同。

---

## 二、AI 产品岗回答框架（黄金 4 层，防"偏技术"）

回答任何"最大阻碍 / 怎么解决 / 最有挑战"类问题时，按从下往上的顺序搭：

1. **痛点 / 场景**（1 句话）：为谁、解决什么。起点，不是全部。
2. **决策 / 权衡（核心）**：为什么选 A 不选 B？放弃了什么？为谁妥协？—— 这是 PM 价值，重点讲。
3. **机制 / 方案（点到即止）**：用产品规则落地，是"设计"不是"写代码"。
4. **验证 / 结果（闭环）**：用户反馈、行为变化、迭代依据。

> 自查口诀：**"去掉所有技术名词，这段话还能成立吗？"** 成立 = 产品视角；不成立 = 你还在用技术撑场面。

---

## 三、AI 应用开发岗回答框架（技术 4 要素）

回答任何技术问题时，按这个结构：

1. **问题**：遇到的技术挑战是什么（量化更好）。
2. **选型 / 架构**：用了什么、为什么这么选（必须有 trade-off）。
3. **实现细节**：关键代码 / 机制怎么落地（讲你真做过的，别编）。
4. **量化效果**：准确率 / 响应时间 / 内测人数 / 稳定性。

> 原则：用"我设计了 X 架构"代替"我负责了 X 业务"；多讲选型的"为什么"；诚实承认短板比硬撑好。

## 五、红线（务必守住）

- **数字只讲简历里可防御的**：FitGenius 种子用户 30+、Atoll 7.5 万下载 / 3.9k Stars、Workisland 内测 20+、LEV0 触达 200+ 可用；长城证券"500+ / 40%"等未核实数字**不讲**，改用"纳入 onboarding 材料 / 建议纳入需求池"等事实表述。
- **技术细节不编造**：未亲眼确认的实现（具体语言特性、第三方库版本）只讲"功能 / 机制"，不补全成你没验证过的代码。
- **内部信息不泄露**：长城证券内部系统 / 数据 / 人名泛化为"某券商"，代码 / 架构可讲方法论，敏感细节不讲。
- **岗位对应简历**：投 AI 应用开发岗发工程版简历，投 AI 产品岗发产品版简历，勿混发（见 `05` / `06` 简历文件）。
