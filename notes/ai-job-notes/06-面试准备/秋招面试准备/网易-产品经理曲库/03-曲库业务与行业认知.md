### 一句话
你是设计**音乐资产管理后台系统**的产品经理——管理歌曲及其信息（元数据）在系统内的登记、分类、上架、质量校验。不是做用户端 App，也不是去谈版权采购。

### 是 / 不是

- ✅ 是"管音乐资产"：管理对象 = 歌曲 + 它的信息（元数据）
- ❌ 不是做用户端功能（不做播放页、不做推荐算法本身）
- ❌ 不是跟艺人对接买版权（那是版权 BD / 商务的活）
- ❌ 不是纯运营执行（JD 写的是"后台系统的产品规划与功能设计"，是产品岗）

- **运营团队**：用你的工具做上下架、打标
- **推荐 / 搜索算法团队**：你整理的元数据是他们的原料
- **技术研发**：你出方案，他们落地

### 日常工作

3. 运营说"批量上架 1 万首太慢"——你设计批量工具提效
4. 用 AI 自动打标签、识别翻唱——探索新功能

### 与你长城证券经历挂钩（面试直接说）
你做的"协同平台"是给客户经理 / 投行用的公司内部产品（to 员工），曲库后台系统是同类的内部运营中台工具——都是中后台 / B 端产品，经验可直接迁移。

## 一、专业名词大白话
- **曲库**：所有歌曲 + 它们的信息，存在系统里的"总仓库"
- **元数据**：一首歌的"档案"——歌手 / 专辑 / 流派 / 语种 / 标签 / 歌词 / 节奏(BPM)
- **入库**：一首歌从"买到了"到"能听到"之间，在系统里登记 + 填信息 + 转码 + 上架的整套动作
- **曲库质量**：数据准不准——歌手标错没、有没有重复、盗版有没有混进来、音质达不达标
- **覆盖率**：目标该有的歌，实际覆盖了多少（比如"华语热歌前 100，你覆盖 95 首"）
- **长尾**：不热门但有人听的冷门歌（长尾占比高 = 曲库更全）
- **中后台 / 后台系统**：公司内部员工用的系统，不是用户用的 App（你做的就是这个）
- **版权生命周期**：一首歌版权"签约 → 上线 → 到期 → 下架 / 续约"的全过程

## 三、网易云音乐概况
- 网易旗下音乐 streaming 平台，2013 上线，2018 港交所上市（9899.HK）
- 核心差异化：歌单社区、乐评文化、个性化推荐、独立音乐人生态
- 面试前查最新：月活、付费用户数、社交娱乐业务承压情况（2025–2026 数据）

---

## 四、音乐行业格局
- **腾讯音乐（TME）**：QQ 音乐 / 酷狗 / 酷我 / 全民 K 歌，版权最全，规模第一
- **网易云音乐**：社区 + 推荐差异化，版权弱势但用户黏性高
- **抖音 / 快手**：音乐分发新势力，短视频带火歌曲
- 关键矛盾：版权成本高 vs 付费率低的行业性难题
