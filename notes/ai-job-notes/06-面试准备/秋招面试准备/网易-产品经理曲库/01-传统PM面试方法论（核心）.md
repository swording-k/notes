# 传统互联网 PM 面试方法论（核心）

> 你原话：「讲项目的方式、回答问题的方式，总是讲得不太对，不像别人上过培训班的。」
> 这份文档就是帮你把「工程师 / Builder 讲法」翻译成「培训班 PM 讲法」。逐字读，按里面的骨架练。

## 一、你现在的讲法 vs 培训班讲法（先照镜子）

| 场景 | 你现在的习惯（工程 / Builder 思维） | 培训班 PM 思维 |
|---|---|---|
| 讲项目 | 「我做了 X，用了 Y 技术，实现了 Z 功能」——功能罗列、实现导向 | 「背景-问题-我的决策-结果-复盘」——决策与影响导向 |
| 回答问题 | 想到哪说到哪，先堆细节 | 结论先行 + 框架拆解 + 数据支撑 |
| 产品题 | 直接甩一个答案 | 先框定问题 → 拆用户/场景 → 给方案 → 说验证 → 说优先级 |
| 数据题 | 凭感觉说「应该涨了」 | 建指标 → 拆维度 → 提假设 → 验假设 → 给 action |
| 缺的东西 | 方法论词汇、结构、数据意识 | 用户画像、闭环、MVP、北极星、AARRR、增长飞轮 |

**核心差异一句话**：工程面讲「我实现了什么」，PM 面讲「我决定了什么、验证了什么、影响了什么」。

## 二、项目讲述的 PM 范式（背这个骨架，顺序不能乱）

任何项目用 5 段讲：
1. **背景 / 问题**：当时业务或用户面临什么痛点？（一句话，能带数字更好）
2. **目标**：我要解决什么？（可量化：提升 X%、降低 Y）
3. **决策与权衡**：我为什么选这个方案、放弃了什么？（这是 PM 最值钱的部分，培训班的人讲得最多）
4. **结果**：上线后数据如何？（哪怕是自测/预估，也要给数字）
5. **复盘**：如果重来，我会怎么改？

⚠️ 你常犯的错误：第 3、4、5 段没有或很弱。工程思维让你爱讲「怎么做的」，但 PM 面试要的是「为什么这么做 + 效果怎样」。

## 三、回答问题的 4 类框架（传统 PM 必考）

### 1. 产品感 / 产品设计题（最高频）
模板：**定义问题 → 拆用户/场景 → 给方案 → 验证 → 优先级**
例：「设计一个老年人用的音乐功能」
- 定义：不是「做个老年版」，而是「解决老人找不到想听的歌 + 操作复杂」
- 用户/场景：独居老人、子女远程帮选、晨练场景
- 方案：大字模式、语音点歌、亲情歌单、极简首页
- 验证：内测 N 人、任务完成率、次日留存
- 优先级：先做语音点歌（最高频痛点）

### 2. 数据分析题
模板：**建指标 → 拆维度 → 提假设 → 验假设 → 给 action**
例：「某功能 DAU 下降 10% 怎么分析」
- 指标：DAU、留存、功能渗透率
- 维度：分渠道 / 分版本 / 分人群 / 分地域
- 假设：新版本 bug / 竞品活动 / 季节性
- 验：拉数据看哪个维度异常
- action：回滚 / 推送召回 / 运营活动

### 3. 估算题（Market Sizing）
模板：**明确口径 → 拆因子 → 给合理假设 → 计算 → sanity check**
例：「中国在线音乐付费用户规模」
- 口径：年付费人数
- 因子：网民 × 音乐用户占比 × 付费意愿
- 假设：10 亿网民 × 70% 听歌 × 15% 付费
- 算：10 亿 × 0.7 × 0.15 = 1.05 亿
- 校验：对比财报公布的付费数

### 4. 行为 / 项目深挖
模板：**STAR + 决策反思**（就是第二节的 5 段）
面试官最爱挖：「你遇到的最大困难」「你和研发冲突怎么解决」「你最失败的项目」

## 四、「上过培训班」的人长什么样（5 个特征，逐条对照练）

1. **结构化表达**：开口就是「我从三个角度看」/「第一…第二…第三」
2. **用数据说话**：任何结论配一个数字，哪怕是估算
3. **有方法论词汇**：用户画像、闭环、MVP、北极星指标、AARRR、增长飞轮、痛点-方案匹配
4. **主动框定问题**：「我理解这个问题的核心是 X，而不是 Y」
5. **结论先行 + 论据支撑**：先给答案，再展开，不铺垫

**你的 3 个具体改进点（基于你的真实习惯）：**
- 改掉「一上来堆技术实现」：PM 面少讲代码，多讲「为什么这么做、效果怎样」
- 改掉「回答问题没有框架」：每次开口前默念「结论—框架—论据」三件套
- 补「数据意识」：讲项目时硬塞一个相关数字（用户量 / 效率提升 / 覆盖模块数）

## 五、传统 PM 面试 vs 你之前面过的岗有什么不同
- 美团 AI Product Builder：偏 Builder，讲「能写 Demo、搭 Agent」很加分 → 你的主场
- 字节 AI 全栈：偏工程，考代码级深挖 → 已验证不适合你（研发序列）
- 网易曲库：偏**传统 PM**，考产品感 + 业务理解 + 表达结构 → **这一套才是你要系统练的**

> 一句话：网易这场，把「框架 + 数据 + 结构化表达」练出来，比纠结曲库业务细节更重要。
