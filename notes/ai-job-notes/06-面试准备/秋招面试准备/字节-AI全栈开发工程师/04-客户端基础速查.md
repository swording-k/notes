## 二、Swift 核心知识点（★ = 必会，可从 FitGenius 讲；无标 = 拓展，会概念即可）

> 面试真实需要的就这几个：**Optional 防崩溃、值类型 vs 引用类型、ARC 内存（weak 防循环引用）、闭包捕获 self**。其余（协议/泛型 POP、Combine）被问到能接话就行。

### 1. Optional（可选类型）
- **是什么**：Swift 中可能有值也可能为 nil 的类型，用 `?` 表示
- **为什么**：强制显式处理 nil，减少空指针崩溃
- **常用操作**：
  - `if let` / `guard let` 安全解包
  - `!` 强制解包（危险，少用）
  - `??` 提供默认值
  - Optional chaining `?.`

### 2. 值类型 vs 引用类型
| | struct（值类型） | class（引用类型） |
|---|---|---|
| 复制 | 深拷贝，复制一份新数据 | 浅拷贝，复制引用/指针 |
| 内存 | 通常在栈上分配 | 在堆上分配 |
| 继承 | 不支持 | 支持继承 |
| 线程安全 | 天然更安全（副本互不影响） | 多线程需注意竞态 |
| 例子 | String、Array、Dictionary、Int 都是 struct | NSObject、自定义对象 |

**面试考点**：Swift 中 String/Array/Dictionary 都是 struct（值类型），和 OC/Java 不同。

### 3. ARC 内存管理
- **ARC = Automatic Reference Counting**，自动引用计数
- **强引用循环（retain cycle）**：两个对象互相强引用，导致谁都无法释放 → 内存泄漏
- **解决**：用 `weak`（弱引用，引用对象释放后自动变 nil）或 `unowned`（无主引用，不持有但不安全）
- **常见场景**：闭包捕获 self、delegate 模式

```swift
// 闭包捕获 self 导致循环引用
{ [weak self] in
    guard let self = self else { return }
    self.doSomething()
}
```

### 4. 闭包（Closure）
- 自包含的代码块，可以捕获外部变量
- 注意捕获列表 `[weak self]` 避免循环引用
- 逃逸闭包 `@escaping`：闭包在函数返回后还可能被执行

### 5. 协议（Protocol）与泛型
- **Protocol**：定义接口，struct/class 都可以遵循。Swift 协议支持扩展和默认实现
- **泛型**：`func swap<T>(_ a: T, _ b: T)`，复用代码，类型安全
- **Protocol-Oriented Programming (POP)**：Swift 推崇用协议组合代替继承

## 三、iOS 核心知识点

### 1. UIViewController 生命周期
```
init → loadView → viewDidLoad → viewWillAppear → viewDidAppear 
→ viewWillDisappear → viewDidDisappear → deinit
```
- **viewDidLoad**：视图首次加载，只做一次初始化
- **viewWillAppear / viewDidAppear**：视图将要/已经显示
- **viewWillDisappear / viewDidDisappear**：视图将要/已经消失
- **deinit**：对象释放，可用来验证 ARC 是否正确

### 2. UITableView / UICollectionView 复用机制（高频）
- **复用池（reuse pool）**：滑出屏幕的 cell 被回收到池子里，滑入屏幕时 dequeue 复用
- **标识符（reuseIdentifier）**：不同样式的 cell 用不同标识符
- **为什么复用**：减少内存占用和创建开销，保证列表流畅滚动
- **注意点**：复用前要重置 cell 状态，避免残留数据

### 3. UI 操作必须在主线程
- UIKit 不是线程安全的，所有 UI 更新必须在主线程执行
- 网络请求/耗时操作在后台线程，完成后切回主线程更新 UI
- Swift 现代写法：`await MainActor.run { ... }` 或 `DispatchQueue.main.async`

### 4. MVC / MVVM / 其他架构
| 架构 | 核心思想 | 优点 | 缺点 |
|---|---|---|---|
| **MVC** | Model-View-Controller | 简单直接 | Controller 容易臃肿 |
| **MVVM** | Model-View-ViewModel | View 和逻辑解耦，便于测试 | 增加一层抽象 |
| **MVP** | Presenter 替代 ViewModel | 职责清晰 | 接口多 |
| **VIPER** | 拆成 View-Interactor-Presenter-Entity-Routing | 模块清晰 | 过重，适合大项目 |

**FitGenius 可答**：我用的是 MVVM，ViewModel 负责 AI 输出解析和业务逻辑，View 只负责展示。

### 5. 网络请求
- **URLSession**：iOS 原生网络请求 API
- 常见步骤：创建 URL → 创建 request → 发起 dataTask → 解析 JSON → 切主线程刷新 UI
- 数据解析：用 **Codable** 协议做 JSON ↔ Model 映射

## 四、移动端性能优化（JD 要求「了解移动端架构设计和性能优化」）

### 1. 卡顿
- **原因**：主线程做了耗时操作（网络请求、大量计算、复杂 UI 渲染）
- **解决**：耗时操作放后台线程；简化视图层级；图片异步加载 + 缓存；避免离屏渲染

### 2. 内存泄漏
- **原因**：循环引用、闭包捕获、通知/KVO 未移除
- **解决**：`weak self`、及时 removeObserver、用 Instruments 的 Leaks 检测

### 3. 启动优化
- **main 之前**：减少动态库、减少 `+load`/`+initialize` 耗时
- **main 之后**：懒加载非必要模块、首屏数据预加载

### 4. 图片加载与缓存
- 异步加载网络图片
- 三级缓存：内存 → 磁盘 → 网络
- 合理压缩和降采样，避免大图

### 5. 电量优化
- 减少定位刷新频率
- 合并网络请求，减少唤醒次数
- 后台任务用合适的 API，避免长期占用 CPU

## 五、Android / 鸿蒙（会概念即可）

### Android 核心概念
- **Activity 生命周期**：onCreate → onStart → onResume → onPause → onStop → onDestroy
- **Fragment**：嵌套在 Activity 里的子页面，有类似生命周期
- **四大组件**：Activity、Service、BroadcastReceiver、ContentProvider
- **RecyclerView**：类似 iOS UITableView，有 ViewHolder 复用机制
- **Jetpack**：Google 官方组件库，ViewModel、LiveData、Room 等
- **ANR**：Application Not Responding，主线程阻塞超过 5 秒会触发

### 鸿蒙核心概念
- **ArkTS**：鸿蒙主力开发语言，基于 TypeScript 扩展
- **Ability**：鸿蒙应用基本组成单位，类似 Activity
- **ArkUI**：声明式 UI 框架，语法类似 SwiftUI
- **分布式能力**：跨设备协同是鸿蒙特色

**面试中一句话带过**：「Android 的 Activity 生命周期和 iOS ViewController 生命周期思想类似；鸿蒙的 ArkTS/ArkUI 我了解过基本概念，还没实际项目经验，但有 SwiftUI 基础，上手应该不慢。」

## 五-B、桌面端框架速查（Electron 等，了解即可，属加分项）

| 框架 | 语言 | 原理 | 备注 |
|---|---|---|---|
| **Electron** | JS/HTML/CSS | 把 Chromium 浏览器内核 + Node.js 打包成桌面 App，前端技术直接写桌面 | VS Code、Discord、字节部分桌面工具用它；你记得的「电脑端」就是它 |
| **Tauri** | Rust + 前端 | 用系统原生 WebView（不打包 Chromium），体积更小、更安全 | Electron 的轻量替代品 |
| **Qt** | C++ / QML | 跨平台原生 GUI 框架 | 工业软件、嵌入式常用 |
| **Flutter desktop** | Dart | 一套代码跑移动+桌面+Web | 跨平台统一 |
| **macOS 原生** | Swift / AppKit / SwiftUI | 苹果官方原生框架 | 字节 Mac 客户端 |
| **WPF / WinForms** | C# / .NET | Windows 原生桌面框架 | 企业软件常见 |
