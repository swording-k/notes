## 一、AI Coding 原理（必考概率最高，JD 明写「了解实现原理有加分」）

### 1. AI Coding 工具是怎么工作的（三层，被问「它内部怎么实现」就答这个）

1. **模型层**：大模型（Claude / GPT / DeepSeek），只负责生成文本（代码 / 决策），自己不执行任何东西
2. **工具层（Function Calling）**：模型输出结构化「调用意图」（工具名 + 参数），运行时真正执行（读写文件、跑命令、搜索），把结果回灌给模型
3. **循环层（Agent Loop）**：think → act → observe 循环，直到任务完成或触发停止条件（步数上限、人工确认）

### 2. 各工具一句话定位（被问「你用过哪些、区别是什么」）

| 工具 | 形态 | 特点 |
|---|---|---|
| Claude Code | 终端 CLI Agent | 整个仓库当上下文，自主多步执行，适合大改造 |
| Cursor | AI IDE | 补全 + Chat + Agent 模式，交互式，适合边写边改 |
| **TRAE** | **字节自家 AI IDE** | 一定提前了解/试用，面试官大概率天天用它 |
| Codex | OpenAI 的编码 Agent | 云端/本地 Agent 执行任务 |
| Copilot | 行级补全鼻祖 | 补全为主，Agent 能力后加 |

### 3. 必须能讲的原理级话题（你的差异化主分）

- **上下文窗口**：token 是计费和记忆单位；对话历史 + 每次工具结果都占用窗口；超了要么截断最早历史、要么压缩总结
- **MCP（Model Context Protocol）**：把「接入工具」标准化的协议——一次开发，所有支持 MCP 的 Agent 都能用。你给飞书 PM Agent 接过 14 个 PM 工具，直接讲这个实例
- **Harness（运行底座）**：模型能力不动，外围工程决定能否安全落地——权限沙箱、工具白名单、步数上限、审计日志
- **为什么要工具白名单**：限制 Agent 能做什么、锁死爆炸半径。你的实证：飞书项目 ALLOWED_TOOLS 白名单 + 4 步上限
- **AI Coding 的局限**（说出来显专业）：幻觉（必须测试兜底）、长上下文衰减（要精简注入）、大重构仍需人拆解任务、生成代码必须人 review
- **你怎么用它提效**（真实工作流）：先让 AI 出计划再动手 → 小步提交 → 让 AI 写测试 → 用白名单/schema 约束输出格式

## 二、项目讲述（STAR，客户端方向主打 FitGenius）

### FitGenius（iOS · Swift · AI 健身计划 App）

- **S/T**：用户用自然语言改健身计划，AI 要把「明天加一组深蹲，去掉卧推」变成 App 能执行的指令
- **A**：① system prompt 强约束 schema + 指令白名单（add_exercise / remove_exercise / update_plan 三个，超出一律兜底）② `extractJSONObject` 括号匹配解析兜底，防模型输出夹带解释导致崩溃 ③ 温度 0 保证稳定
- **R**：AI 输出崩溃率≈0；单次结构化输出比多轮 Agent 延迟低，适合移动端
- **深挖预案**：
  - 为什么不用 Agent 循环？→ 场景单一（改计划），单次结构化输出够用，循环只会加延迟加成本——**按场景选范式**
  - 为什么白名单锁 3 个指令？→ 锁死爆炸半径，模型再怎么幻觉也出不了这个集合

### 飞书 PM Agent（Python · DeepSeek Harness）

- 需求≠任务领域模型（M:N 关系 + RTM 跟踪）
- 默认跑 Harness：Agent Loop + 工具白名单（14 个 PM 工具）+ 4 步上限（防上下文膨胀）
- 加分点：这是「企业内部 Agent 落地」的完整认知——模型选型、工具设计、安全约束、防崩兜底全链路都碰过

## 三、技术方向基础（主推客户端，另两个会概念即可）

### 客户端（iOS / Swift）——主攻方向，FitGenius 直接支撑

- Swift：Optional 是什么；值类型(struct) vs 引用类型(class)；ARC 内存管理；闭包；协议
- iOS 基础：App 生命周期；UIViewController 生命周期；**UITableView 复用机制**（高频）；MVC / MVVM；UI 操作必须主线程
- 网络：URLSession 发请求 / RESTful API / JSON 解析（FitGenius 实例直接接上）
- 性能（了解即可）：卡顿 = 主线程阻塞；循环引用 → 内存泄漏 → weak/unowned 打破

### 前端（会概念就够）

- React：组件化；props vs state；虚拟 DOM（diff 减少重绘）；Hooks（useState / useEffect）
- TypeScript：给 JS 加静态类型，大型工程减少运行时错误

### 后端（会概念就够，JD 原文点名这四件套）

- **数据库**：索引加速查询（B+树），代价是写入变慢、占空间
- **缓存**：Redis 内存读写快，挡在数据库前面
- **消息队列**：解耦、削峰、异步
- **RESTful API**：URL 表资源、HTTP 动词表操作（GET/POST/PUT/DELETE）、状态码表结果

**全栈态度**（JD 第 4 条就要这个）：主动说「我主攻客户端，后端在学 Python，有 AI 工具辅佐学得很快」——诚实 + 正好踩中他们要的热情。

## 五、计算机基础口答 10 题（技术面间隙常被抽问）

1. TCP vs UDP：TCP 面向连接、可靠、有序；UDP 无连接、快、不可靠
2. 三次握手：syn → syn+ack → ack，确认双方收发能力都正常
3. HTTP vs HTTPS：HTTPS = HTTP + TLS 加密，默认端口 443
4. 进程 vs 线程：进程独立内存空间；线程共享进程内存
5. 死锁四条件：互斥、持有并等待、不可剥夺、循环等待
6. 数据库索引：B+树加速查询，代价是写入变慢 + 占空间
7. 事务 ACID：原子性、一致性、隔离性、持久性
8. 缓存穿透/击穿/雪崩：查不存在的数据（布隆过滤器）/ 热点 key 过期瞬间打崩库（互斥锁）/ 大量 key 同时过期（过期时间加随机）
9. 消息队列三大用处：解耦、削峰、异步
10. RESTful：URL 表资源、HTTP 动词表操作、状态码表结果
