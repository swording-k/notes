## 1. 一分钟口述稿（背这段，自然说就行）

> 我做的是一个叫**怪相馆（MemeLab）**的微信小程序，2026 年 10 月从 0 到 1 上线。
>
> **出发点**是我在微信聊天里观察到：大家用的表情包高度同质化，但凡把**熟人的照片**做成"离谱小动作"的梗，点击欲和转发欲明显更高——现成表情包没有这个"身边人梗"的钩子。
>
> 所以我把产品定义成一句话：**"一张照片 + 一个离谱小动作 = 几秒出一个会动的怪表情"**，专门给微信、抖音这些聊天窗口做表情包用。
>
> **产品上我做了三件关键决策**：
> 第一，**降低创作门槛**——给了 14 种预设（变猫、捏脸、融化、漏气…）加自由捏图，照片/视频双工作台，一键导出循环 GIF，不用注册、无水印；
> 第二，**把 AI 能力编排成可控的创作链路**——接了阿里通义万相，打通"一句话生图 → 自然语言改图 → 生成约 2 秒动作 → 剪辑配字 → 导出 GIF"四段闭环，而且**每一步让用户单独确认，不静默连调**，避免乱扣费；
> 第三，**我独立设计了生成式功能的成本和商业化模型**——按供应商原价核算单张生图价格，做了分步报价、版本化计价，配套点数账户、每日免费额度和激励广告解锁。
>
> **约束上**我把"合规和可验证"当产品红线：照片默认本地处理、玩法链接不带照片，还接了微信内容安全检测并按审核意见整改。
>
> 现在迭代到 0.4.5，微信端能搜到"怪相馆"使用。这个项目让我完整跑了一遍"用户洞察 → AI 产品定义 → 商业化设计 → 合规落地"的全链路，我觉得和万兴做 AIGC 创意工具的思路特别像。

## 2. 把"产品思考"讲出来的四个层次（面试官深挖时往这四个方向引）

### 2.1 用户洞察（最该讲透）
- **真问题**：表情包是社交刚需，但市面表情包"千篇一律、没有身边人梗"。熟人照片 + 离谱动作 = 更强的情绪共鸣和转发冲动。
- **为什么是现在/为什么是我**：AI 生图成本降到可用，普通人也能几秒出梗图，但**缺一个"零门槛、本地、不上传隐私"的工具**。
- 这对应万兴 JD 的"深入用户与市场挖掘创新机会"——你这就是。

### 2.2 产品定位与功能设计决策
- **核心定位**：不是"AI 画图工具"，是"聊天场景里的表情包生产器"。定位不同，功能取舍不同（重导出 GIF、重本地、重预设，而不是重出图质量参数）。
- **14 种预设 vs 自由捏图**：预设降低首因门槛（新手秒出），自由捏图留住深度用户（可局部拉拽、鼓起、撤销叠加）。这是"渐进披露"的产品策略。
- **双工作台（照片/视频）**：覆盖"我有一张图"和"我有一段视频"两种输入，最大化使用场景。

### 2.3 AI 能力编排（最显技术产品素养）
- **链路**：一句话生图 → 自然语言改图 → 生成约 2 秒动作 → 剪辑取景配字 → 导出 GIF。
- **为什么这么切**：每一步都是"用户能单独确认 + 单独付费/扣点"的原子能力，而不是黑盒一键出片——**可控 = 可计价 = 可防滥用**。
- **动作两种输入**：文字写动作 / 参考视频学动作（2–6 秒参考视频让角色模仿）。这是"降低动作描述门槛"的设计。
- **模型选型**：阿里云百炼通义万相，API Key 只存云端函数、客户端不含密钥（安全设计）。

### 2.4 商业化与合规（万兴最看重，因为万兴自己就靠 AI 积分赚钱）
- **成本模型**：按供应商原价核算单张生图成本 → 这是做 AI 功能的前提（不核算就瞎补贴）。
- **计价设计**：分步报价 + 版本化计价 + 点数账户 + 每日免费额度 + 激励广告解锁。一句话讲清：**让免费用户有甜头、让重度用户付费、用广告兜住边际成本**。
- **合规红线**：照片本地处理、玩法链接不含照片（隐私）；接入微信内容安全检测、按审核意见整改（平台合规）。这两点体现你"做 AI 产品有边界意识"——万兴这种上市公司极在意。

## 3. 高频深挖问答（提前备好答案，别现场编）

**Q：你这个 AI 链路成本到底怎么算的？免费用户你亏多少？**
A：单张生图按通义万相官方原价计入成本；我设计了"每日免费额度（比如 N 张）+ 超出走点数/广告"的结构，免费层是获客成本不是亏损黑洞，重度用户和广告补贴边际成本。具体数字以供应商报价为准，我的重点是**建立了"成本可核算 → 计价可分档"的机制**，而不是拍脑袋补贴。

**Q：你为什么不用 Stable Diffusion / 即梦，用通义万相？**
A：选型看三点——① 国内合规（数据不出境顾虑小）；② API 成熟度与中文语义改图能力；③ 成本可控、Key 可云端托管。万相在中文自然语言改图场景足够，且和微信生态同在国内云，时延和合规都友好。

**Q：用户真会用吗？有没有数据？**
A：目前是 0.4.5 刚上线/审核通过后开放阶段，重点在验证"会不会用"而不是"有多少量"。我更想讲的是**产品机制设计如何驱动留存**（预设降门槛、自由捏图留深度用户、GIF 无水印利于传播）。如果有内测反馈数据就甩，没有就老实说"刚上线，重点在机制验证"。

**Q：你一个人做的？开发和产品都是你？**
A：对，**我是独立 owner**——需求定义、玩法设计、交互、开发全链路自己跑（网页版 + 原生微信小程序 + CloudBase 后端 + 209 项自动化测试）。这也逼着我把"产品决策"和"技术实现"打通，正好契合万兴要的"AI 原生、能独立把想法做成可运行产品的人"。

**Q：和万兴喵影/Filmora 的 AI 能力比，你这个有什么不同？**
A（显格局）：万兴是专业级视频创作工具，我做的是一个**极轻量的"聊天表情"垂直场景**。但底层逻辑一致——都是"AI 能力 + 可控编排 + 商业化闭环 + 合规"。如果我来万兴，我最有兴趣的是把这种"原子能力 Skills + 可控创作链路"的思路，复用到你们天幕/剧厂的产品化上。

## 4. 防守提示（别踩雷）

1. **小程序上线状态别夸大**：简历写"微信搜索怪相馆使用"，但 GitHub README（10-29）写的是"已提交审核、结果尚未公布"。现场统一口径 = **"0.4.5 已提交微信审核、刚开放/即将全量，内测阶段"**，别拍胸脯说"已经几万用户"。面试官问起就讲机制和设计，不聊虚的量级。
2. **支付/真实交易没验收**：你设计的是"计价模型"，不是"已经收到钱"。讲成"商业化方案设计"，别讲成"已经在赚钱"。
3. **AI 效果有边界**：README 明说"AI 仅少量真实样本，不保证任意提示词都满意"。被问到效果就坦诚，转回"产品机制如何兜底（分步确认、参考视频学动作）"。
4. **别把开源协作的活和 MemeLab 混**：MemeLab 是你**独立 owner**；WorkIsland/Atoll 是 Collaborator。两个故事分开讲，别让面试官觉得你分不清 ownership。
5. **技术名词只对确认过的**：通义万相、CloudBase、原生小程序、GitHub Pages CI、209 项测试——这些 README 有，可讲；别临时加"我用了 XXX 框架"除非你真知道。
