> 权威说明：本文件是仓库结构与同步约定的**唯一权威来源**，Mac / Windows 两侧 WorkBuddy 只读此文件、照此执行，勿另建并行文档（如曾出现的「工作流设置.md」「mac-sync.sh」）。

## 二、人物关系图（Obsidian Graph）约定

Obsidian 的「图谱」视图由**笔记文件 + `[[wikilink]]`** 自动生成，无需额外配置。

连接逻辑（四层，有章法）：
- **入口 = `00-知识库入口`**：只连三条主线，作为打开 vault 后的第一站。
- **中心 = `我`**：`我.md` 连接各位同事 / 导师，以及 `工作日记`、`产品地图`。
- **主轴 = `工作日记`**：`工作日记.md` 底部只连接 `日期索引/YYYY-MM-DD`。
- **日期 = 中转层**：每个日期节点连接当天正式产出。
- **叶子 = 各产出**：每个产出笔记末尾的「关联笔记」连回对应日期节点，不直接连 `工作日记`。

规则：
0. **从入口开始**：打开 Obsidian 后先看 `00-知识库入口.md`，不要直接在全局图谱里找散文件。
1. **一人一笔记**：每个人物在 `人物/` 目录下建一个 `姓名.md`，并用 `[[我]]` 连回中心。
2. **用 wikilink 互链**：笔记正文里用 `[[姓名]]` 指向相关人物，图谱据此画出关系边。
3. **MOC 总图**：`人物关系图.md` 连接 `我`、`工作日记` 与**各位同事**（同事写成 `[[wikilink]]`，让人物关系图连着我们这些人）；产出类节点仍以纯文字列出，避免成为抢中心的枢纽。
4. **README 同步**：在 README 的「👥 人物关系」表中新增人物行，但**只用纯文字、不加 `[[wikilink]]`**，否则同事节点会被 README 反向连上、图谱变乱。

新增人物的标准动作：
1. `人物/新姓名.md` 写节点笔记，用 `[[wikilink]]` 连到「我」；
2. 在 `人物关系图.md` 的「中心」一节补一行 `[[新姓名]]` wikilink（让人物关系图连上这位同事）；
3. 在 `README.md` 人物关系表补一行（纯文字，不加 wikilink）。

新增产出的标准动作：
1. 在 `工作产出/日期/` 下写笔记，末尾加「关联笔记」连回 `[[日期索引/YYYY-MM-DD|YYYY-MM-DD]]`；
2. 在对应 `日期索引/YYYY-MM-DD.md` 的「当日产出」补一行 `[[新产出]]`；
3. `工作日记.md` 只补日期节点，不直接补产出链接。

新增产品研究素材的标准动作：
1. 放入 `产品研究/`，不要塞进某一天的正式工作产出目录；
2. 在 `产品研究/README.md` 补 wikilink；
3. 如果它已经可以作为阶段性成果，再在对应日期索引补一行。

全局图谱默认设置：
- `.obsidian/graph.json` 默认过滤 `工作产出/`、`remotion-videos/`、`.workbuddy/`，只看知识骨架。
- 若要看某天具体产出，打开对应 `日期索引/YYYY-MM-DD.md` 后使用局部图谱。

## 三、双机同步工作流（防冲突核心）

**核心原则**：GitHub 远端是唯一真相源；先拉后改、改完即推；小步提交优于一次性大提交。

每台机器（Mac / Windows）都遵循：

| 时机 | 命令 |
|------|------|
| 坐下开始工作前 | `git pull --rebase origin main` |
| 完成一个逻辑单元（一条笔记 / 一个章节） | `git add -A` → `git commit -m "..."` |
| 当天收工 / 切换机器前 | `git push origin main` |

要点：
- **每次修改都要 push（用户 2026-07-09 明确指令）**：完成一个逻辑单元（一条笔记 / 一个章节 / 一次文件增删）即 `git add -A` → `git commit` → `git push origin main`，不必等切换机器；保证远端始终最新，Mac 侧随时 pull 即得最新。
- **`.obsidian/workspace.json` 已 gitignore**：它记录窗口布局 / 打开的标签页，在两台机器上差异巨大且无意义，忽略它可消除绝大多数「假冲突」。
- **避免双机同改同段**：本仓库只有你一人维护，只要「切换机器前先 push、开工前先 pull」，几乎不会冲突。
- 万一真冲突：git 会标记 `<<<<<<<` 冲突块，手动选正确一侧后 `git add` + `git commit` 即可。

## 四、给 WorkBuddy 智能体的指令

- 每次动手改仓库前，先执行 `git pull --rebase origin main`。
- 改动按逻辑单元提交，提交信息用中文简要说明。
- **每次修改后务必 `git commit` + `git push origin main`（用户 2026-07-09 铁律：只要做过修改就更新 GitHub）**。
- 新增人物严格按「第二节」规范，保持 wikilink 连通。
- 不提交公司源码子仓库、`*.log`、`remotion-videos/node_modules/`。`.workbuddy/` 若已经记录跨机同步、自动化或冲突处理，可随逻辑单元提交；普通临时缓存不要单独提交。
- 本仓库由 WorkBuddy 统一管理（Mac / Windows 同一套），不要另建「工作流设置.md」「mac-sync.sh」等重复说明/脚本，规范以本文件为准。
- 若 Windows 侧曾设置过「每日定时自动 pull+push」类自动化（如 `automation-1783505990772`），请禁用之——它等于多出一个自动管理者，破坏「单一管理者」原则，会引发双机冲突。
