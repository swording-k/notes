- 开展行业竞品分析与 AI 助手技术架构 / 落地可行性研究，形成分析结论，**为协同平台 v3 规划中商机广场等模块的功能设计提供支撑**。

### 二、后期：项目管理智能体（PM Agent）—— 从 0 到 1 产品设计
- 独立负责飞书群聊项目管理智能体的产品设计与落地：从团队项目管理的实际痛点出发，设计并在飞书（Aily Agent）上实现该智能体，目前已被两个团队投入使用；后续拟将流程标准化、可移植，探索自研路线，扩展为企业级智能体。
- 设计"**需求 ≠ 任务**"领域模型（多对多关联 + 需求追踪矩阵 RTM），厘清需求（做什么 / 为什么，含验收标准）与任务（怎么做）的边界，解决此前 PM 流程讲不清、验证不客观的痛点。
- 撰写 PRD v4.0，实现并验证 F1–F13 共 13 项核心功能；沉淀《领域模型与业务逻辑》文档与操作手册，作为智能体可移植、可对接自研底座的知识层。

## 🔴 面试防守 / 红线（投递前必读）

1. **产品定位要准确**：手拉手协同平台、商机广场是公司真实在用的内部系统，你做的是**研究 / 教学 / 宣发支撑**，不是工程开发。别写成"开发 / 研发了协同平台"。
2. **PM Agent 已落地试用，但"企业级"是未来方向**：它已在飞书（Aily）上实现并被两个团队投入使用——这是真实落地，面试可大方讲。但必须能说清**是哪两个团队、他们用它做什么**（背调 / 追问时能接住）；"探索自研 / 扩展企业级"是后续规划（你已用"拟 / 探索"措辞），**别说成"已完成企业级部署"**。
3. **量化只用真实计数**：5 面板、7 板块、13 项功能都是真实的；**不要编造**阅读量、播放量、效率提升百分比、"触达 500+" 这类数字（除非你能向导师要到真实数据）。
4. **不冒领他人成果**：不把导师 / 团队的 ownership 写成自己的；v3 相关只写"提供支撑 / 分析结论"，不写"主导 / 负责 v3"。
5. **表述可升级、事实不造假**：动词可以结果导向（"负责 / 产出 / 设计 / 验证"），但不虚构头衔与数据。
