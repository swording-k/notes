## 📚 已掌握的关键信息

### 手拉手协同系统

**核心定位**：券商内部「撮合 + 分润」平台。把分支机构（有客户）与总部业务条线（有专业能力）之间的私下人情协作变成制度化的线上流程。

**存在原因**：
- 证券公司天然存在分支机构（有客户资源缺专业能力）vs 总部（有专业能力缺客户渠道）的结构性矛盾
- 过去靠私人关系对接，容易跳单、无分润保障、无合规留痕
- 2025年初一把手提出「把利分好」，推动系统化解决

**三大业务场景**：
1. 投行业务协同（IPO、并购等）
2. 研究院协同（行业研究需求）
3. 财务确认（收入分配落地）

**当前状态**：一期已上线运作，二期开发中（测试环境 `ccc-uat.in.cgws.com/synergy-platform/`；详见《手拉手协同系统-学习与思考》（2026-07-09 澄清）。另有 PC 端。

### 关键角色速查

| 角色 | 一句话职责 |
|------|-----------|
| 客户经理（分支机构） | 维护本地企业客户关系，发现商机后发起协同 |
| 投行对接人（总部） | 承接 IPO/并购等专业服务 |
| 研究员（研究院） | 提供行业/产业链分析 |

| 营业部/分公司负责人 | 审批知会，保护部门利益 |

**同步节奏（防冲突核心）**：

| 时机 | 命令 |
|------|------|
| 开工 / 编辑前 | `git pull --rebase origin main` |
| 完成一个逻辑单元 | `git add -A && git commit -m "..."` |
| 收工 / **切换机器前** | `git push origin main` |

- **何时必须 push**：① 切换机器前；② 当天收工；③ 要让另一侧智能体基于最新状态工作时。不必每次 commit 都 push。
