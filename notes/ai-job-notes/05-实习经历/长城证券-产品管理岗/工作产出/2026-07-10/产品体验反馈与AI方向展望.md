## 一、背景：为什么写这份反馈

入职一周以来，我以「用户」身份实际体验了测试环境的各产品，并进行了 PC 端与手机端的跨端对比。作为产品岗位的实习生，我希望将使用过程中的真实感受整理成结构化反馈，为产品迭代提供参考。

以下反馈按**优先级**排列：P0 为影响核心流程或造成明显体验断层的问题；P1 为影响效率或一致性的问题；P2 为锦上添花的优化项。

## 二、认知更正：手机端「商机广场」与 PC 端「商机挖掘」是定位不同的独立产品

> **更正与致谢（重要）**：本问题原稿将"手机端商机广场 vs PC 端商机挖掘 前端能力差异大"列为 P0，怀疑两端"范式错位 / 缺乏统一 Feature Spec 自然漂移"。**经导师指正、并参考其发送的《PRD_商机广场》(v1.2) 后确认：两者本就是定位不同的独立产品，前端差异属正常设计，并非缺陷。** 特此更正，并感谢导师发送 PRD 厘清我的理解偏差。

#### 两端定位对比（依据 PRD 与实测）

| 维度 | PC 端「商机挖掘」 | 手机端「商机广场」 |
|------|----------------|------------------|
| **产品类型** | 企业跟踪 / 研究工具（PC 端功能模块） | 移动端投行并购重组商机撮合应用（独立 App，React Native） |
| **核心动作** | **发现并跟踪**目标企业（"我要盯住哪些公司"） | **发布并撮合**商机需求（"我有一条需求要找人对接"） |
| **主要场景** | 客户经理日常维护客户、为发起协同做准备 | 全员浏览/发布投融资需求、促成对接 |
| **关键能力** | 关注企业、拜访、联系人、企业360、产业链、舆情 | 商机提报（结构化/问答式/语音转写+NLP）、审核评级、认领撮合、个人中心 |
| **与「协同」关系** | 是发起协同的**上游**（先有企业，再申请协同） | 是协同的**来源之一**（看到需求→发起协同） |

#### 结论
- 手机端「商机广场」是 PRD 明确定义的**独立移动端产品**：商机提报 → 运营审核评级 → 发布 → 认领 → 撮合，与 PC 端「商机挖掘」（企业研究/跟踪）的**目标用户与核心动作完全不同**，不应强行对齐。
- 原 P0 的判断（统一领域模型 / 跨端能力矩阵 / 强制两端对齐）**不成立，撤除**。
- 此条从"待改进问题"更正为"理解记录"，**不计入下方待改进项**；下文 P1/P2 仍聚焦于手机端商机广场自身的体验优化，不受此影响。

## 三、P1 — 效率与一致性优化

### 问题 2：发布表单前向锁定 + 缺草稿保存（实测支持回退，非阻塞）

#### 现状描述

从「发布商机」截图与实机操作可以看到：
- 顶部有 5 步步骤条：①商机概况 → ②企业信息 → ③详细需求 → ④联系信息 → ⑤预览提交
- 当前停留在第 1 步（商机概况），显示商机类型选择（7 类）、标题输入、有效期选择
- 底部有红色「下一步」按钮
- **实测结论**：① **支持回退**——进入后续步骤后，可点击回到上一步修改已填信息；② **前向受限**——在填完当前页必填项之前，不能点「下一步」进入后续步骤，也无法跳步预览后面的字段。

#### 问题分析

经实机验证，**回退修改是支持的**，因此这并非阻塞性的体验缺陷——用户不会因填错而被卡死。本处不再作为重点问题，仅保留两点可选的效率增强观察：

1. **后续步骤不可预览**：填写第 1 步时，看不到第 3 步「详细需求」具体要填哪些字段、需准备什么材料。对 B2B 场景（涉及企业信息、估值、交易结构）而言，提前知道"后面要准备什么"有助于一次性备齐资料。
2. **无草稿自动保存**：截图中未见「保存草稿」入口。若在第 3 步填写大量文字后中断（来电 / 切 App），存在会话过期导致内容丢失的风险。

#### 建议（可选，非紧急）

- **未来步骤只读预览**：允许点击后续步骤标签查看字段清单与提示（不可编辑），让用户提前知悉需准备的材料。
- **草稿机制**：每完成一步后台自动存草稿；「我的 → 我发布的」增加「草稿箱」入口；再次进入时提示「是否继续上次填写？」。

#### 预期收益
降低长表单中断导致的填写丢失风险；让用户在开始前即了解全部所需材料，提升一次性填写效率。属于体验锦上添花，不阻塞主流程。

### 问题 3：「最新发布 0 / 今日+0」的零数据状态展示策略

#### 现状描述
数据看板第一张卡片大字显示「0」，副标题「今日+0」。在测试环境或初期上线阶段，这种展示方式可能会让早期用户感到「这个功能没人用」。

#### 建议
- 当今日新增为 0 时，改为显示**累计值**（如「本月 +12」或「本周 +5」），避免单日零值的消极暗示
- 或在零数据状态下插入轻量的引导文案/空状态插图（如「暂无新商机，点击右下角 + 发布第一条吧～」）
- 参考：飞书/钉钉的空状态设计——用鼓励性文案替代冷冰冰的数字 0

## 四、P2 — 锦上添花



### 问题 4：个人中心成就体系可进一步深化
「我的」页面的成就卡片（已成功撮合 1↑ / 已发布 2 / 已对接 2 / 已收藏 2）是一个很好的 Gamification 起点。未来可考虑加入：月度贡献排行榜、连续活跃天数徽章、部门协同指数对比等，驱动内部使用积极性。

## 补充条目：智能助手能力现状与升级机会

> 个人注记：我看到亚琴姐在企微私有版中建了一个聊天 bot，在和她对话，我个人对 AI agent 方面比较了解。以下作为补充观察提出。

**现状（基于 test 环境实测）**：导师账号已在企微私有版中接入该 Bot，但当前能力有限——主要只能读取公司内部文档做简单问答，**连基础的外部 API（如天气查询）都尚未接入**，更不具备操作业务系统的能力。

**与市面成熟产品的差距**：这与飞书智能伙伴、企业微信中的 OpenClaw（"龙虾"）等 To C 成熟产品的"数字员工"形态差距明显——后者已能管理文档、日程，并在群聊中作为数字员工协作提效。

**技术可实现性（简述）**：企业微信私有版已提供消息、身份、各业务系统的开放 API，技术上是"地基齐全"；只需在其上自建 LLM Agent 调度层 + 工具调用（Function Calling）能力，即可让助手从"问答盒子"升级为"能动手的数字员工"。金融合规场景下，大模型与 Agent 应私有化部署在自有服务器，确保数据不出域。

**一点判断**：我们理解团队的目标是私有部署、内部自用，而非对外做成通用产品。因此**从零自研一套对话基座并无必要**（如果 AI 只做到"读文档做简单问答"（就像 test 截图那样），那真就成了"私有化部署一个落后版飞书"。）——市面上即便做也难敌飞书/企业微信的投入。更务实的路径是：**参考其技术架构，将大模型 / Agent 部署到我们自己的服务器上**，优先接入长城长已有的业务 API（协同、商机、舆情等），分阶段释放效率（长城长的 AI 不该是通用问答 bot，而该是**懂"协同/分润/商机"业务语义的领域 Agent**（比如"帮我发起一条投行协同并按历史比例预填分润方案"）。）。

## 五、总结

以上 4条商机广场相关反馈 + 1 条智能助手补充观察中：原列 P0 的「手机端商机广场 vs PC 端商机挖掘 差异」**经导师指正与《PRD_商机广场》确认，实为两款定位不同的独立产品、差异属正常设计，已从问题更正为认知记录（见第二节），不计入待改进项**。其余待改进项：发布表单前向锁定+缺草稿（问题 2，实测支持回退、非阻塞，可选优化）、零数据状态展示（问题 3）、成就体系深化（问题 4）；智能助手那条作为补充观察，供团队规划下一版时参考。

其余 P1/P2 可根据开发资源排期逐步推进。

作为刚接触产品的实习生，我的分析一定有不够成熟之处，欢迎导师和团队指正。我会在接下来的工作中继续深入体验各板块功能，争取提出更多有价值的意见。
