| **流程咨询** | 协助梳理工作流程、推荐效率工具与实操建议 | 未实测（仅声明） |

### 1.2 边界与局限（从对话中暴露）

| 用户提问 | Bot 回复 | 暴露的问题 |
|----------|---------|-----------|
| 「明天天气如何」 | "作为AI助手，我无法实时获取天气数据。请提供您所在的具体城市，或建议您直接查看手机天气应用..." | ❌ **无外部 API 对接**——连天气都查不了，更别提调用内部系统 |
| 「你是哪家公司的」 | "我是企业微信的智能助手，主要为为企业员工提供日常工作咨询与帮助。" | ⚠️ 回答泛化，没有体现长城证券/长城长的品牌身份定制 |

### 1.3 与 PC 端「AI协同助手」的关系

根据《手拉手协同系统新人教学文档》第七节，PC 端有一个「协同学院 → AI协同助手」模块，定位是"类似 ChatGPT 的对话式 AI 助手，专门为手拉手的业务场景训练"，典型用法包括："北交所上市的条件是什么？""可交换公司债和普通公司债有什么区别？"。

**推测**：PC 端的 AI 协同助手和手机端 test 环境的这个 Bot 是同一套后端的两个前端入口——一个嵌在 PC 协同学院面板里，一个以独立 Bot 形式存在于企业微信会话列表中。

## 二、对标分析：我们离「数字员工」还有多远？

你提到的 OpenClaw / 飞书智能助手 / 企业微信 AI 助手，它们的「数字员工」形态远超当前的简单 Q&A Bot。以下是对标矩阵：

| 维度 | 当前长城长 AI 助手 | 飞书智能伙伴 / 企业微信 AI | 差距等级 |
|------|-------------------|--------------------------|---------|
| **对话能力** | 单轮/多轮问答，基于预设知识库 | 多轮对话 + 上下文记忆 + 意图识别 | 🟡 中 |
| **知识范围** | 公司制度/人事/行政/IT + 业务问答 | 全面的企业知识库 + 公共知识 + 实时联网搜索 | 🟡 中 |
| **工具调用（核心差距）** | ❌ 无——不能操作任何系统 | ✅ 可读写文档/表格、管理日历/日程、发起审批、查询 CRM、在群内@触发动作 | 🔴 **大** |
| **群聊中的角色** | 私聊 Bot，未看到群场景 | 作为群成员被 @ 时响应，可执行群相关操作（总结聊天记录、创建待办） | 🔴 **大** |
| **个性化** | 无记忆，每次对话独立 | 记住用户偏好/角色/部门，提供差异化服务 | 🟡 中 |
| **多模态** | 仅文本 | 文本 + 图片理解 + 文件解析 | 🟡 中 |
| **主动触达** | 被动等待提问 | 可定时推送日报/提醒、监控异常并主动通知 | 🟠 中大 |

### 核心结论

**当前 AI 助手 = 一个包装了企业知识的通用 LLM 对话界面**（可能接了一个 RAG 知识库），而飞书/企微的 AI = 一个**能操作系统工具的 Agent 架构**。

两者的本质区别不在于"对话有多聪明"，而在于**能不能动手干活**。

## 三、「数字员工」应该能干什么？（针对长城证券场景）

既然导师想在下一版加强 AI 助手，那就不只是"把对话做更好"，而是要往 Agent 方向走。以下是基于长城证券实际业务场景的「数字员工」能力设想：

### Tier 1 — 基础能力（本次迭代可落地）

| 能力 | 场景示例 | 技术路径 |
|------|---------|---------|
| **业务知识问答增强** | 不只答制度，还能结合商机广场/协同管理的实时数据回答："我有多少条待处理的协同？""本周新发布了几条商机？" | 接入现有后端 API，LLM 做 SQL/Natural Language → API 调用 |
| **文档读写** | "帮我把这条商机的信息整理成一份简报" / "帮我润色这封给客户的邮件" | 接入文档引擎（类似飞书文档 API 或自建） |
| **流程引导** | 用户问"怎么发一条商机"，Bot 引导式地一步步带着用户完成（而非甩一段文字教程） | 对话流 + 状态机，逐步调用表单接口 |

### Tier 2 — 进阶能力（下一阶段目标）

| 能力 | 场景示例 | 技术路径 |
|------|---------|---------|
| **协同流程代理** | "帮我发起一条关于 XX 公司的投行协同" → Bot 自动填好基础信息、关联客户、提交，用户只需确认 | Agent + 工作流引擎集成 |
| **信息聚合通知** | 每天早上推送："您关注的 3 家企业中有 1 条新增舆情 / 您有 2 条协同待处理 / 本周到期 1 条商机" | 定时任务 + 多数据源聚合 |
| **群聊协作** | 在项目群里 @AI助手 "总结一下今天的讨论要点并生成待办清单" | 群消息 hook + NLP 摘要 + 待办创建 |

### Tier 3 — 远期愿景

| 能力 | 场景示例 |
|------|---------|
| **跨系统编排** | "帮我查一下 XX 公司的最新舆情，如果有重大负面，自动在我的拜访记录里加一条提醒" |
| **数据分析** | "上个月我们部门的协同完成率是多少？按业务类型拆解一下" → 直接出图表 |
| **培训教练** | 根据用户的协同历史，推荐需要补的业务知识（如"你最近发了 3 条投行类协同，建议看一下北交所上市条件"） |

## 四、关于「是否重头做」的回答

> 你的疑问：既然企业微信/飞书已经有成熟的 AI 助手，长城长是基于企微私有版开发的，他们没提供这个功能吗？导师是在重头做吗？

### 4.1 企业微信确实有官方 AI 能力

腾讯在企业微信中已经推出了**企业微信 AI 助手**（基于混元大模型），能力包括：
- 对话问答（内置知识库）
- 文档摘要/生成
- 邮件撰写
- 部分系统集成（日程、审批等）

但这里有个关键点：**企业微信官方 AI 是面向所有企业的通用方案**。对于长城证券这样的金融机构：

1. **合规隔离要求**——金融行业的数据不能随便传到腾讯公有云的大模型里。企微官方 AI 是否支持私有化部署或数据不出域，取决于合作模式。
2. **业务深度绑定需求**——企微通用 AI 不知道什么是"商机挖掘""协同申请""分润结算"。这些是长城长/手拉手独有的业务概念。
3. **定制化程度**——如果要用企微官方 AI 来覆盖手拉手的全部业务问答，相当于要把整套业务逻辑"喂"给它，且受限于官方开放的 API 和插件能力。

### 4.2 导师的选择大概率是「半自建」

从截图看，当前这个 Bot 已经在做**企业知识库问答**（休假制度等），这说明至少知识层是自建的（RAG + 内部文档）。但完整的「数字员工」Agent 架构（能操作系统、能在群聊里执行动作）目前还没有。

所以更准确的判断是：
- **不是完全从零开始**——基础对话框架已经有了（可能是接了某个 LLM API + RAG）
- **也不是直接用企微官方 AI**——因为需要深度绑定长城长/手拉手的业务系统和数据
- **最可能的路线**：在已有对话能力基础上，**逐层接入长城长的业务 API 和工具链**，让它从一个"问答盒子"变成一个能干活的"数字员工"

### 4.3 这对产品意味着什么？

如果你想在导师面前展示产品思维，**与其问"为什么不直接用飞书的"，不如问"我们的 AI 助手可以逐步接入哪些业务能力来变成数字员工"**——前者是在质疑决策，后者是在推动建设。
