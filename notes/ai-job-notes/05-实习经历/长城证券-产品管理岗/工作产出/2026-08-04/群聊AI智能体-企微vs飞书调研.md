# 群聊内 AI 智能体做项目管理：企业微信 vs 飞书 调研（草稿 / 研究输入）

> 说明：本文件由 WorkBuddy 整理官方资料（企业微信开发者中心、飞书开放平台、飞书 aily、2026 公开报道）而成，是**调研输入稿**，不是给导师的最终文档。向导师汇报前请用户本人用自己的话改写，避免「AI 味」。

## 一、任务理解（先对齐）
- **目标**：验证一种「群聊即项目管理系统」的协作方式——在办公软件（企微/飞书）的群聊里放一个**能真正干活**的 AI 智能体；成员用聊天 / 写注解的方式推进项目，AI 自动把对话转化成任务、进度、文档。
- **路径**：先拿「软件开发项目」试，跑通后复制去金融业务。
- **现状**：导师在企微只试出「能聊天的 BOT」，没有「能工作的智能体」。让探索飞书是否能做，最好出个 demo 拉人进来试这种协作方式行不行。

## 二、平台要具备什么能力（评价维度）
1. 群聊入口：能 `@` 一个 bot/agent，且它能**接收**群消息（不只是发）。
2. 能**读群上下文** + 能**写回结构化数据**（任务表 / 文档）。
3. 能**主动提醒 / 汇总 / 派活**。
4. **权限隔离**：不同人看到 / 能改的数据不同。

## 三、企业微信：架构与能力
### 1) 群机器人（webhook 消息推送）
- **单向通知**：向群发消息（文本/图片/卡片等），**不能收、不能回**。本质是个 HTTP POST 管道。
- 用途：系统告警、日报周报推送。**不是 agent**。

### 2) 智能机器人（2026 新能力）
- 管理员或被授权成员可建；支持「AI 自动生成 / 手动 / API 模式」三种方式。
- API 模式可对接自有模型与数据；支持**插件（MCP）** + **工作流**（分支/循环/HTTP 请求/执行 Python）。
- 可加入单聊 / 群聊，`@` 它即可问答。
- **门槛**：需管理员在【管理后台 → 安全与管理 → 管理工具 → 智能机器人】开启创建权限并审批；单企业最多 300 个、单人最多 20 个。

### 3) 「大圆」AI Agent（腾讯原生，WAIC 2026 亮相）
- 原生智能助理，左滑唤起；能**感知群聊 / 文档 / 邮件 / 会议**等上下文。
- 能提炼群聊核心议题、拆行动项、指派责任人、一键把待办发到相关群。
- 可能需企业开通 / 灰度。

### 企微小结
- 企微「能做」的 agent 靠 **智能机器人（自建，需管理员）** 或 **大圆（平台能力，需开通）**；webhook 机器人不算。
- 导师试出的「只能聊天的 BOT」大概率是 webhook / 旧版问答机器人，没接数据底座与工作流，所以「不能工作」。

## 四、飞书：架构与能力
### 1) 开放平台机器人（开发者 API）
- 接收群事件、卡片交互回复，全功能、可编程，适合深度定制。

### 2) 多维表格智能体（最贴合本任务）
- 把一张正在用的**多维表格**变成「团队 AI 同事」。
- 三次点击创建；可进群 `@`，**查数 / 填进度 / 写报告 / 催事项**，结果写回表格。
- 触发器：记录新增 / 修改 / 评论 / 定时 → 主动工作。
- 权限继承多维表格高级权限，不同人答案不同。
- **这就是「群聊内 AI 做 PM」的低代码实现**。

### 3) 飞书 aily（原生 AI 伙伴）
- Agent 形态常驻通讯录；读群聊 / 会议 / 文档**主动干活**；专业版可做业务分析。

### 飞书小结
- 飞书原生就有「智能体进群做项目管理」的完整拼图；**多维表格智能体零代码即可出 demo**，最贴合需求。

## 五、对比结论
| 维度 | 企业微信 | 飞书 |
|---|---|---|
| 群内 `@` 接收消息 | 智能机器人 / 大圆（需管理员或开通） | 机器人 / 多维表格智能体（开箱） |
| 低代码出 demo | 需管理员建智能机器人 | 多维表格智能体，零代码 |
| 数据底座 | 文档 / 微盘 / 自建应用 DB（需自搭结构） | 多维表格（天然项目表）+ 云文档 + 任务 |
| 主动提醒 / 派活 | 大圆较强 | aily + 多维表格智能体较强 |
| 金融复制 | 可，受合规与数据不出域约束 | 可，受合规与数据不出域约束 |

## 六、关于「企业微信管理员到底是谁」
- **管理员** = 创建并管理「长城证券」这个企业微信组织（租户 / workspace）的账号，通常在公司 **IT / 信息化 / 金融科技研发中心**里负责数字办公、协同平台的团队。
- **怎么找**：
  - 问导师（雅琴姐）/ 一聪哥——他们内部用过企微，大概率知道谁管；
  - 问金融科技研发中心的行政 / IT 接口人；
  - 走公司 IT 服务台 / 信息化部工单。
  - 实习生通常在企微 App 里看不到「我 → 管理企业」入口（那是管理员才有的）。
- **关于 WorkBuddy 的企微连接器**：你扫的那个二维码，是让 **WorkBuddy 作为「第三方应用 / 机器人」接入长城证券的企微**，需要企业管理员在后台审批授权；且券商合规通常会卡。这条通路对你「做 demo」既不现实也非必需——**别把它和你要搭的「群聊 AI 智能体」混淆**：前者是让 WorkBuddy 读你的企微，后者是用企微 / 飞书平台自己的机器人框架搭一个 agent。

## 七、建议的 demo 路线（待你确认）
- **路线 A（最快验证概念）**：用飞书多维表格智能体，建一张「软件开发项目」表，把智能体拉进群，演示 `@` 它建任务 / 催进度 / 写周报。**零代码，半天可出**。
- **路线 B（贴合企微现状）**：请导师 / 管理员开通企微智能机器人或「大圆」，在企微群演示。依赖管理员。
- **路线 C（不依赖平台，先验证协作写法）**：用 WorkBuddy 模拟「AI 群聊 PM」原型，证明这种写作 / 注解方式能转成任务与进度，再映射到平台能力。
- **我的建议**：先走 A 出个能演示的活样例给导师看，再谈复制金融业务与企微落地。
