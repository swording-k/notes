## 工作习惯

### 日常学习
1. 在 **Trae** 中写代码（Claude 辅助）
2. 在 Obsidian 日记里记录笔记
3. 晚上把日记整理到对应笔记

### 刷题流程
1. LeetCode 函数模式：理解算法思路
2. Trae ACM 模式：练习输入输出
3. 写完发给 Claude：整理到仓库

### 读书流程
1. 主教材在 `09-开源书库/`，按 [[09-开源书库/README]] 的顺序读
2. 读书笔记写到 `07-AI应用工程师知识/`，不直接改书稿
3. 每章读完后回到对应概念笔记补链接

### Obsidian 笔记规范（重要！）
**所有自己写的笔记必须使用 Obsidian 内部链接格式**，这样才能在 Obsidian 中点击跳转。

```markdown
# 正确格式
[[笔记名]]                    # 链接同目录笔记
[[文件夹/笔记名]]              # 链接子目录笔记
[[../上级目录/笔记名]]         # 链接上级目录笔记
![[截图名.png]]               # 嵌入图片

# 示例
今天学了 [[两数之和]]，用到了 [[哈希表]] 的思想。
详见 [[../04-代码练习/刷题清单]]

# 错误格式（禁止使用）
- [文字](链接)              # 这是网页链接，不是内部链接
- /绝对路径.md               # 绝对路径不能用
```

**例外**：`09-开源书库/` 内的教材保留原始相对链接，不批量改写成 wikilink。

**Claude Code 写笔记时必须**：
- 用 `[[]]` 代替普通链接
- 用相对路径（如 `../`）而非绝对路径
- 嵌入截图用 `![[图片.png]]`
- 在 Trae/VSCode 写的笔记，Obsidian 打开后链接依然可点击
- 新增笔记后，回到 [[README]] 和对应目录说明里挂链接

## 代码存放规范

### 目录命名
- 每个题目用 **LeetCode 题号** 命名，如 `0198-打家劫舍`、`0070-爬楼梯`
- 格式：`XXXX-题目名`，不足 4 位前面补 0

### 文件结构
每个题目目录下包含：
- `XXXX-题目名.md` - 原题 + 题解（**必须包含原题链接**）
- `XXXX-题目名.py` - 代码模板

### 文档要求（必须遵守）
1. **原题链接**：每个题目文档开头必须包含 `> 原题链接：https://leetcode.cn/problems/xxx/` 格式
2. **题目描述**：完整原始描述
3. **输入输出格式**：题目要求的输入输出
4. **示例**：示例输入输出
5. **思路解析**：状态定义、转移方程、初始化
6. **代码实现**：带注释的完整代码
7. **面试问答**：常见面试问题（如有）

1. **过期计划的处理**：不直接删，移到 `00-学习规划/历史归档/`。
2. **面试材料归位**：所有面试文件只能放在 `06-面试准备/` 的对应阶段和「公司-岗位」目录里，不能留在 `05-实习经历/` 或其他目录。
3. **面试状态**：每个岗位在 `06-面试准备/README.md` 里标记状态（进行中 / 已结束 / 已接受），结束后保留材料。
4. **删除内容前先确认**：只删除明确过时或重复的文件；用户点名要删的除外。
5. **开源书库**：
   - 仅保留阅读版，不复制 `.git`；
   - 更新时从 `~/Desktop/GitHub书库/` 重新同步；
   - 保留各书 `LICENSE` 和署名，协议为 CC BY-NC-SA 4.0。
6. **提交范围**：本目录属于 `~/Desktop/notes` monorepo，提交时只提交 `notes/ai-job-notes/` 下的改动，不带上 `ielts-study`、`claude-config-notes` 等无关改动。
7. **文档同步**：用户提出的新要求、新规范、聊天中达成的共识，必须实时更新到 CLAUDE.md、README.md 和知识地图.md，不能停留在旧版本。
8. **Obsidian 配置**：`.obsidian/` 随仓库同步（配置 + 插件），方便别人 clone 后直接使用；`workspace.json`、插件 `data.json`、缓存不入库。monorepo 根 `.gitignore` 只对 `notes/ai-job-notes/.obsidian/` 放行。

## 给 Claude 的建议

- 用户是初学者，解释要详细，代码要拆解
- 用户容易焦虑，需要鼓励 + 具体行动建议
- 优先回答代码问题，再整理笔记
- 发现问题及时指出（比如语法错误）
- **讲解任何知识时的要求**：
  1. 讲清楚**是什么**、**为什么**、**怎么用**
  2. 知识点要能举一反三，不只是这道题
  3. 细节不跳过，每个步骤都要解释
  4. 讲完要确认用户理解，不理解就再讲
  5. **重点细节必须展开讲**：
     - 虚拟头节点（dummy）为什么需要？解决什么问题？
     - 快慢指针的步长、间隔、为什么这样设置
     - 每一步操作改了什么、指向哪
     - 边界情况怎么处理
     - 用具体数字从头到尾走一遍流程
  6. **知识沉淀**：讨论出的新知识点必须同步到对应笔记（概念笔记或刷题笔记）
  7. **题解 md 文件要求**：
     - 包含原题链接
     - 包含题目描述
     - 思路解析要讲透每个细节，不跳过任何步骤
     - 代码要有注释解释关键行
     - 面试问答（如果有常见面试问题）
